Restaurant schema markup: a copy-paste JSON-LD example

Schema markup is a block of code that states your restaurant's name, address, hours and menu address in a form machines read without guessing. Google requires two fields and recommends ten more. This page gives you a working example, explains each field, and shows how to test it.

Published November 23, 2026 Last checked November 2026 ~8 min read

What schema markup does a restaurant website need?

Add one JSON-LD block using the Restaurant type on your home page or location page. Google's Local business documentation requires name and address, and recommends geo, telephone, url, openingHoursSpecification, priceRange, servesCuisine and menu. Every value must match what a visitor can read on the page. Test it in Google's Rich Results Test.

Markup does not guarantee a ranking or any special display. It reduces guessing. It also keeps your hours, phone number and menu address consistent when a machine reads your site. That matters most when a person asks an assistant a plain question, such as when you close tonight.

Start with the visible page

The example restaurant

The markup below describes a made-up restaurant. Its details are shown here in plain text, because markup must describe content that is visible on the page. Your page should show the same facts in the header, footer or a contact block.

Harbor Street Kitchen

Seafood and Pacific Northwest dishes, $$

214 Harbor Street, Tacoma, WA 98402 · (253) 555-0148

Hours: Tuesday to Thursday 11:00 a.m. to 9:00 p.m.; Friday and Saturday 11:00 a.m. to 10:00 p.m.; closed Sunday and Monday.

Menu: harborstreetkitchen.example/menu/

Fictional business and reserved example domain. Replace every value with your own.

The process

Add Restaurant schema in six steps

  1. Use the most specific type

    Google's Local business documentation says to use the most specific subtype available. For a restaurant that is Restaurant. A bar can use BarOrPub, and a bakery Bakery. You can give an array of types if one business is two things.

  2. Fill the two required fields

    name and address. Write the name exactly as it appears on your sign and Google profile. Use a full PostalAddress with street, city, region, postal code and country.

  3. Add the recommended fields you can keep accurate

    Add telephone, url, geo, priceRange, servesCuisine, menu and openingHoursSpecification. Google asks for latitude and longitude with at least five decimal places. Only add what you will update. A field you forget to maintain becomes a wrong fact.

  4. Point menu at your text menu page

    Google's documentation names the menu property: for food establishments, the fully qualified URL of the menu. Schema.org also defines hasMenu, and it accepts a URL or a full Menu object. Use a text page, not a PDF. For the page itself, see restaurant menu SEO. For item-by-item markup, see its Menu structured data section.

  5. Describe regular hours, and keep the date-bound ones separate

    Use one OpeningHoursSpecification per group of days with dayOfWeek, opens and closes. Google documents validFrom and validThrough for seasonal closures and says a day the business is closed all day sets both opens and closes to "00:00". Holiday handling has its own page: holiday and special hours.

  6. Validate, publish, and inspect

    Paste the code into the Rich Results Test and fix critical errors. After publishing, use the URL Inspection tool in Search Console to see how Google reads the live page. Test again after every menu or hours change.

Copy and edit

The JSON-LD for Harbor Street Kitchen

Put this inside a script tag with type="application/ld+json", once per page. Remove the comments line in your copy, since JSON has no comments.

{ "@context": "https://schema.org", "@type": "Restaurant", "name": "Harbor Street Kitchen", "url": "https://harborstreetkitchen.example/", "telephone": "+12535550148", "servesCuisine": ["Seafood", "Pacific Northwest"], "priceRange": "$$", "menu": "https://harborstreetkitchen.example/menu/", "address": { "@type": "PostalAddress", "streetAddress": "214 Harbor Street", "addressLocality": "Tacoma", "addressRegion": "WA", "postalCode": "98402", "addressCountry": "US" }, "geo": { "@type": "GeoCoordinates", "latitude": 47.25288, "longitude": -122.44429 }, "openingHoursSpecification": [ { "@type": "OpeningHoursSpecification", "dayOfWeek": ["Tuesday", "Wednesday", "Thursday"], "opens": "11:00", "closes": "21:00" }, { "@type": "OpeningHoursSpecification", "dayOfWeek": ["Friday", "Saturday"], "opens": "11:00", "closes": "22:00" } ] }

Sunday and Monday are left out because the restaurant is closed. The values match the example card above, line for line.

Use the international phone format and 24-hour times. Get real coordinates from a map tool.

Avoid these

Five mistakes that make markup worse than none

  • Markup that disagrees with the page. If the page says closed Mondays and the code says open, a machine has two answers.
  • One block copied to every location. Each location page needs its own address, phone and hours.
  • Hours that never change. Update the code the same day you change hours on Google. A stale block outlasts the people who wrote it.
  • Marking up content that is not on the page. Do not add cuisines, awards or prices a visitor cannot see.
  • Expecting FAQ results. Google removed FAQ rich results in May 2026. Write FAQs for your guests, not for a display.

If an assistant gives a wrong answer about your restaurant, the cause may be a stale copy elsewhere. See how to fix a wrong menu on Google.

Questions

Restaurant schema questions

Do I need schema markup for my restaurant website?

No, it is not required to appear in search. It helps because it states your name, address, hours and menu address in a form machines read directly. Google's documentation names name and address as required for the Local business type. If the markup is wrong or out of date, it does more harm than leaving it out, so only add it if you will maintain it.

Which schema type should a restaurant use?

Use Restaurant, which is a more specific type of LocalBusiness. Google's Local business documentation says to use the most specific subtype available. If you run a bar, a bakery or a cafe, there are more specific types for those. If a business is two things, you can give an array of types.

Where do I put the JSON-LD code on my site?

Put it in a script tag with type application/ld+json, in the head or body of the page it describes. Use it on your home page if you have one location, or on each location page if you have several. Use one block per page, and make sure every value matches what a visitor can read there.

Should I add my star rating to my restaurant schema?

No. Google's documentation says aggregateRating and review are intended for sites that collect reviews of other local businesses, not for markup about your own business. You can still show reviews on your page for guests. Just leave your own rating out of the structured data.

How do I test my restaurant structured data?

Paste your code or page address into Google's Rich Results Test and fix critical errors. After publishing, use the URL Inspection tool in Search Console to see how Google reads the live page. A passing test does not mean Google will show anything special. It means the code is readable and consistent.
